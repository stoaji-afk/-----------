# Solid Order Service

Пример приложения на Go, демонстрирующий принципы **SOLID** и **Dependency Injection**.

## Стек

- **Go** 1.21+
- **SQLite3** (`github.com/mattn/go-sqlite3`)
- Поддержка PostgreSQL (заглушка)

## Структура проекта

```
.
├── main.go              # Точка входа, DI-конфигурация
├── model/               # Модель данных, репозитории, нотификаторы
│   ├── model.go         # Интерфейсы, константы, реализации
│   └── model_test.go    # Тесты model
├── service/             # Бизнес-логика
│   ├── service.go       # OrderService
│   └── service_test.go  # Тесты service
├── go.mod
└── go.sum
```

## Запуск

```bash
go run main.go
```

```
┌─────────────────────────────────────────────────────────┐
│                      main.go                            │
│                                                         │
│  sql.Open("sqlite3")                                    │
│  ┌───────────────────────┐  ┌───────────────────────┐   │
│  │ model.NewSQLite       │  │ model.NewEmailSender  │   │
│  │ Repository(db)        │  │ model.NewSMSSender    │   │
│  │ model.NewTelegram     │  │                       │   │
│  │ Notifier()            │  │                       │   │
│  └──────────┬────────────┘  └──────────┬────────────┘   │
│             │                          │                │
│             ▼                          ▼                │
│     ┌─────────────────────────────────────────┐         │
│     │   service.NewOrderService(repo, notifier)│         │
│     │   svc.CreateOrder("Иван", [...], 10.5)  │         │
│     └─────────────────────────────────────────┘         │
└─────────────────────────────────────────────────────────┘

model.go — константы:
  - OrderStatusPending = "pending"
  - EmailNotifyFormat, SMSNotifyFormat, TelegramNotifyFormat
  - OrderCreatedMessage
  - MainOption1, MainOption2, MainOption3

service.go — использует model.OrderCreatedMessage

Тесты:
  - model/model_test.go  — 10 тестов (константы, нотификаторы, Order)
  - service/service_test.go — 7 тестов (CreateOrder, mock-репозиторий)
```

## Что изменилось

| Аспект        | До                          | После                              |
|---------------|-----------------------------|------------------------------------|
| Магические строки | Хардкод в коде           | Константы в `model`                |
| Статус заказа   | `"pending"`               | `OrderStatusPending`               |
| Форматы сообщений | `fmt.Printf("...")`     | `fmt.Printf(EmailNotifyFormat)`   |
| PostgreSQL      | `SERIAL`                  | `GENERATED BY DEFAULT AS IDENTITY` |
| Тесты           | Отсутствовали             | 17 тестов с mock-реализациями      |

## Архитектура

Проект следует принципам **SOLID**:

- **SRP** — каждый тип отвечает за одно: репозиторий хранит данные, нотификатор отправляет, сервис orchestrates
- **OCP** — новые нотификаторы/репозитории добавляются без изменения сервиса
- **LSP** — все реализации `Notifier` и `RepositoryWriter` взаимозаменяемы
- **ISP** — интерфейсы минимальны и специфичны
- **DIP** — `service` зависит от абстракций `model`, не от конкретных реализаций

### Охват тестами

**model:**
- Константы (`OrderStatusPending`, форматы уведомлений, `OrderCreatedMessage`)
- `EmailSender` — `Send`, `Notify`
- `SMSSender` — `Send`, `Notify`
- `TelegramNotifier` — `Send`, `Notify`
- Структура `Order`

**service:**
- Успешное создание заказа (`CreateOrder_Success`)
- Ошибка репозитория — сервис возвращает ошибку, нотификатор не вызывается (`CreateOrder_RepoError`)
- Ошибка нотификатора — сервис возвращает ошибку (`CreateOrder_NotifierError`)
- Пустой список товаров (`CreateOrder_EmptyProducts`)
- Нулевая сумма заказа (`CreateOrder_ZeroTotal`)
- Делегирование `Notify → Send` (`CreateOrder_NotifyDelegatesToSend`)
- Инициализация сервиса (`NewOrderService`)
